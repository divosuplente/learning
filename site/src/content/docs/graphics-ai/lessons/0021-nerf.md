## The Core Idea

A **NeRF** is a neural network that learns a *function*:

```
f(position, viewing_direction) → (color, density)
```

- **Position** — a 3D point (x, y, z) in the scene
- **Viewing direction** — the angle you're looking from (θ, φ)
- **Color** — RGB at that point, from that direction (view-dependent: reflections change with angle)
- **Density** — how "solid" the point is (0 = empty space, high = solid surface)

The network doesn't store geometry explicitly. It *is* the scene — you query it at any position and direction to find out what's there.

## How Rendering Works

To produce a new image from a camera pose:

1. Cast a ray from each pixel through the scene
2. Sample points along each ray
3. Query the network at each sample: get color + density
4. **Volume rendering** — accumulate colors along the ray, weighted by density, using the alpha compositing equation

This is different from rasterization (draw triangles) or ray tracing (bounce light rays). It's *volume rendering*: the scene is a fog of colored densities, and you see through it proportionally.

**Why it looks so good:** The network can represent view-dependent effects — specular highlights, reflections, translucency — because it takes viewing direction as input. A shiny surface returns different colors from different angles, and the network learns this from the training photos.

## How Training Works

1. Collect 50–200 photos of a scene from different angles
2. Use COLMAP (structure-from-motion) to estimate camera poses for each photo
3. Train the network so that rendering from each training pose reproduces the original photo
4. Loss = difference between rendered and actual pixels → backpropagation adjusts the network

Training takes **hours** (often 8–24h on a single GPU). But once trained, the network *is* the scene — no mesh, no textures, no manual cleanup.

## Why It's Slow at Inference

Rendering a single 800×800 image requires:
- 640,000 rays (one per pixel)
- ~64 sample points per ray
- A network forward pass for each sample point

That's ~41 million network evaluations per frame. Even with optimization, you're looking at **seconds per frame**, not milliseconds. The original 2020 NeRF paper took ~30 seconds per frame.

## The Tradeoff

| Aspect | NeRF |
|--------|------|
| Quality | Excellent — smooth, view-dependent effects |
| Training time | Hours |
| Render speed | Seconds per frame (not real-time) |
| Storage | Small (a few MB for the network weights) |
| Editability | Hard — the scene is implicit in the weights |

For interview fluency: NeRF is **implicit** (geometry lives inside a network you can only query) and **slow to render** (volume rendering is expensive), but produces the **highest quality** novel views. The industry moved toward explicit representations (Gaussian Splatting) for real-time rendering — see the next lesson.

## Analogy

Think of NeRF like a hologram: the information for every viewpoint is encoded in one medium. You don't "extract" a mesh from a hologram — you look at it from different angles and the image changes. That's exactly what querying a NeRF does.
